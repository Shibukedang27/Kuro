# Collection IDs are internal; removing wrap still needs a semantic boundary

## Decision: separate storage observability from language behavior

This test/documentation increment starts directly above draft/open [PR #121](https://github.com/Shibukedang27/Kuro/pull/121), exact parent `d3fca419d3fdf327f154df94930c6c1807640766`. Production source, generated distribution artifacts, admission points, resource ceilings, and runtime algorithms are unchanged.

Under the delegated design discretion, classify `VMNextCollectionId`, `VMCollectionIds`, and `VMCollectionOwners` as **private authored-VM representation state**, not a supported source-language introspection API. Existing direct-helper assertions remain valuable implementation regression witnesses; their literal field contents are not a permanent representation requirement. This decision adds no reserved `VM` namespace: programs may use these ordinary identifiers. They are data in the VM's environment, not aliases of its outer helper variables. The new production-dispatch controls exercise that distinction and show that a bytecode call to an undeclared `VMResetCollection` Action cannot invoke the outer helper.

Evidence for that classification is the VM's own environment description and declarations ([`vm.kuro`, lines 1–41](../../self_host/vm.kuro)), the separate bytecode-variable storage and function lookup, and the absence of these fields from the public spec, built-in action registry, and source compiler. Absence of documentation alone would not establish a compatibility waiver. The new tests are bounded controls, not a sandbox/security-isolation proof.

**Do not confuse a private schema with unobservable consequences.** The [seeded signed-boundary witness](../../tests/self_host/test_vm_generation_id_bounds.py) reaches different activity/append outcomes on hosted and Linux x86-64 execution. Native wrap is not adopted here as a portable language guarantee; neither is it removed. Classifying fields as private does not authorize changing supported collection behavior after a long sequence of public operations. The existing wrap witness remains unchanged. No natural `2**63`-reset execution, Darwin/ARM wrap policy, or authored-generator boundary parity is established.

Consequently, retain the production representation. The precise unresolved migration decision is whether the supported collection-history domain excludes generation exhaustion, or whether a deliberately specified replacement exhaustion policy is acceptable. This note makes neither choice: a source-level behavior change is outside this safe increment. A finite-domain contract must be explicit, not inferred from a 65,536-row buffer: empty resets can advance IDs without paying rows.

The follow-up [history compatibility gate](vm-generation-history-compatibility.md) makes the interim engineering rule explicit: preserve existing backend-observable behavior, including exhaustion/history effects, until a separate contract decision authorizes a change. This does not settle portable language overflow semantics; it rules out silently narrowing histories to enable a counter-free migration.

## What each consumer borrows

The [new IR regression guards](../../tests/self_host/test_vm_collection_consumer_contract.py) close the call/effect graph of all ten generation-ledger helpers and census direct consumers of the counter, ID column, and owner column. They also protect live scratch across nested calls. A new edge, effect, consumer, or selected write-order change requires a fresh review. These checks are deliberately implementation-sensitive tripwires, not a theorem about arbitrary IR, indirect alias analysis, or native memory.

| Consumer | Current capture and lifetime | Migration obligation |
| --- | --- | --- |
| Find / Mark / Reset / Deactivate | Name slots are retained; activity means ID `>= 0`. Reset replaces an ID without freeing historical rows. | Preserve slot and scalar-overwrite precedence. An active-empty `-2` head cannot use the existing nonnegative-ID activity predicate. |
| Append | Capture selected ID; admit row; write owner, raw, display; increment logical count last. | Preserve the admission point and write boundaries. A chain tail search adds work; a tail table adds metadata and failure boundaries. |
| Get / Length | Capture ID, scan owner rows. Negative Get calls Length before scanning; the nested helper cannot overwrite Get's protected scratch. | Preserve negative normalization, selected chain, failure/display behavior, and scratch lifetime. Length is not a mutator. |
| Set | Capture ID; replace raw then display in one selected row; no row debit. | Preserve eager-copy independence and sticky failure. Consecutive writes are not recoverable atomic publication. |
| Copy | Self-copy check precedes lookup. Capture source ID before resetting destination; capture raw/display before each append. | Preserve late source lookup and exact partial prefix. A linked candidate must additionally capture the next link before append; today's owner layout has no next link to validate. |
| Stack marker / list store / Print | A collection-kind stack entry holds a **name**, not an ID. Store copies eagerly; Print resolves the name again. | Do not turn a late-bound marker into a pinned generation/head. Print's helper loop has no user callback, but this does not make an arbitrary dispatch graph non-reentrant. |
| Get result / scalar stack / Action frame | Raw value and display are copied into distinct scalar/result/frame slots. Source reset must not rewrite a captured pair. | Preserve display and kind erasure, caller result initialization, frame cleanup, failure publication, and backend Text lifetime. |

The relevant implementation ranges in [`vm.kuro`](../../self_host/vm.kuro) are 144–364 (ledger), 366–409 (result/stack), 426–546 (load/store/frame), 782–857 (Action invocation), 1095–1168 (load/list store), and 1347–1462 (Get/Length/Set/Append/Print). There is **no closure capture table or closure object operation in this VM**. Its explicit Action frames are not evidence that the compiler's other closure machinery is safe to migrate.

The audited helper graphs are synchronous, nonrecursive, and have no Input, Print, dynamic invocation, or VM-dispatch edge; the admission intrinsic is a compiler-private leaf. The scratch guards check Get across Length, source ID across destination Reset, and source ID/position/raw value across Append. `VMAppendCollectionDisplay` is intentionally consumed and cleared by Append, not falsely treated as immutable scratch. These constraints do not establish moving-Text stability, asynchronous pins, row reuse, sharing, or reclamation safety.

## New bounded behavior checks

The [scalar consumer probes](../../tests/self_host/test_vm_collection_consumer_values.py) execute complete unchanged production helpers in nine hosted and nine Linux x86-64 native cases. They cover first, last/negative-first, too-negative, at-length, active-empty with historical rows, inactive, missing, and an eager snapshot after source Set/reset. Every case retains four paid historical rows. Valid raw/display captures survive a later destructive reset and a failed helper read. Hosted state inspection additionally verifies numeric-zero invalid-Get fallback. Native invalid cases verify failure and empty display, **not a printable Text interpretation of that fallback**.

Four additional [production-dispatch scenarios](../../tests/self_host/test_vm_publication_roots.py), each hosted and native, check internal-name isolation, non-invocation of outer helpers, Get scalar/display survival in both stack and `_` after source reset, and stopping before user Print after a failed Get. Earlier controls in that module still pin late name binding, scalar deactivation, eager alias isolation, Action-frame propagation, argument kind erasure, global-collection/frame precedence, and partial publication. None installs a counter-free reader.

### A probe failure that must not become a parity claim

The first direct-helper probe printed the failed Get's captured raw fallback through a variable inferred as Text. Five invalid native cases terminated with signal 11, while hosted execution printed numeric `0`. Successful cases did not crash. The failed helper returns numeric zero through an otherwise Text-valued raw channel; treating that zero as a native Text pointer is not a valid fallback-rendering test. The corrected probe branches on its captured failure flag and prints a literal failure tag instead, while checking the actual fallback value only through hosted state inspection.

The separate bytecode-dispatch failed-Get control verifies that normal authored VM execution stops before the following user Print. This isolates the direct diagnostic misuse; it does **not** certify every caller or resolve the runtime's erased scalar/Text ABI. No production bug fix or full native fallback-value parity is claimed. A future migration must review failure publication and typed/erased return consumers rather than treating the corrected probe as proof of a safe printable sentinel.

## Representation cost and next path

This patch has zero production allocation, storage, runtime-cost, peak, or headroom change. The [counter-free model](vm-counter-free-row-identity.md) still demonstrates 32,640 next-link reads for 256 appends without a tail table; that is cumulative algorithmic work, not wall-clock timing. Current Append does not scan historical owner rows after name lookup; Get/Length/Set/Copy do. A chain layout trades those scans against append traversal and is not an unconditional speedup. The field-count suggestion of reusing IDs for heads and owners for next links is still not a native bounded-buffer implementation or a system-allocation proof.

Before migration: define the supported exhaustion/history boundary; choose an acceptable tail strategy with measured workload cost; prove linked-row and Text lifetimes on each backend; preserve hosted dynamic growth; and prove seed handling, every admission/write/failure boundary, marker/scalar/frame integration, and churn/alias behavior in the actual replacement. Keep current production behavior until those obligations are met. If supported full native wrap must be preserved, the purely counter-free candidate remains ruled out.

Acceptance uses focused and full tests, independent exact-head review, a fresh four-image bootstrap rebuild, blocked-toolchain smoke, compiler reproduction/272-literal control, and exact-head CI. Results belong in the immutable PR receipt, not as inherited certification. Historical full-compiler peak remains 65,481 rows with 55 spare, not a measurement made here. Python seeding and Clang/LLVM still block strict independence; PR #107/#108 remain individually unverified. Keep this and all earlier PRs draft/open/unmerged.
