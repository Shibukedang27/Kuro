## The frontend now owns one rejection rule

The authored source compiler now has a bounded validation stage between parsing and lowering. [ADR-0013's Text-only Length contract](ADR-0013-type-system-stage7.md) is enforced for known operand types: non-Text produces E3009 instead of being lowered into `BC_LENGTH` and left for a backend to reject. Known Text remains accepted, including Text-element collections under the existing element-type model. This does not introduce collection-shape typing or re-enable integer-owner native Length.

The new [Kuro-authored validator](../../self_host/lengthcheck.kuro) uses three iterative, parsed-token phases sharing one scan loop. First it collects top-level base declarations, explicit typed assignments and homogeneous bare-literal assignments; the first known binding wins, not the last runtime value. Nested-only declarations/assignments do not become global type facts. Second it collects Compare-result Symbols without replacing established global types, matching the reference resolver's completed symbol table before typechecking. Third it checks Length using the active Action header's parameter tokens and Repeat's Integer Index overlay. Two Integer frame columns restore the outer Action-header position and Repeat depth; rows are reused by nesting depth instead of retaining every closed block. Parameter tokens are not copied into extra collections. Keyword-looking bindings use the parser's own declaration disambiguator with its cursor saved and restored; this also correctly handles conditions whose variable is named `is`. String contents are never treated as statements. Successful parsing guarantees statement terminators and bounded token lookahead; failed parses do not enter the scans.

All scans require successful parsing. On the first known non-Text Length, the compiler records E3009, line, column and message, then blocks lowering and bytecode encoding. No IR, bytecode or compiler artifact is published for that rule failure. [Both source composers](../../compiler/self_host.py) use the same stage order; the [shell composer](../../bootstrap/compose-native-compiler-source.sh) checks extraction markers and exactly one stage entry in one fail-fast operation. The standalone lowerer/encoder and runtime composition are unchanged.

The diagnostic caret is at the **Length keyword**, matching the Python reference's statement span. The existing standalone authored typechecker uses the target token instead; its implementation is unchanged. The hosted compiler helper includes E3009 and its source location in `SelfHostError`. The production native protocol remains exit 1 with exactly `kuro.compile-error/1\n`; it does **not** newly print a human-readable E3009. Native code/location/message records are exercised through a freshly built diagnostic probe.

## What this does not validate

This is not full resolver/typechecker integration. Other E3/E4 checks remain bypassed by the authored source compiler, including undefined-name checking and assignment compatibility. An annotation accepted by this narrow scanner is not a proof the assigned runtime value has that type.

Unknown is not Text. Variable-reference aliases, computed RHS expressions, mixed literal initializers and nested-only assignment/declaration types remain unclassified. The special result binding `_` remains unknown. `Items = 11, 22; Alias = Items; Length Alias;` therefore still compiles through this frontend; native owner-alias generation remains separately rejected. No alias propagation, flow-sensitive reassignment typing or scalar/collection-shape inference is claimed. Collection sizes, GET bounds, generator admission rules, platform qualification and storage/token ceilings are unchanged.

**Scope-aware behavior is not complete reference-validator parity.** Python's current Length check consults global `symbols.types` directly, ignoring Action-parameter and Repeat-Index overlays. The existing authored typechecker consults parameter types and gives Index Integer treatment. This compiler stage honors actual parameter windows, lets an untyped parameter shadow a known global with unknown, and treats Index as Integer only inside Repeat. Thus typed Text parameters can shadow Integer globals, typed Integer parameters can shadow Text globals, and a Text global Index is restored after Repeat. These boundaries are explicitly tested; neither validator was silently rewritten. Compare facts are collected before validation, unlike the existing authored combined pass's source-order handling. Aligning the complete semantic implementations is separate work.

The raw/runtime-VM composition still bypasses this compiler-only gate and retains its low-level collection Length operation. A frontend rejection is not a claim of native Text-Length generator support or of validation on every raw bytecode/runtime route.

## Why not wire both full semantic passes now?

The existing resolver/typechecker composition would activate many unrelated diagnostics and carries an inherited hosted recursion limit on a 272-literal initializer. This increment deliberately does not broaden that integration. Its iterative scanner preserves the maximum initializer control and is executed as part of the compiler's own bytecode, not merely included in a larger source artifact.

An early prototype failed the self-compiled-bytecode gate because its symbol lookup used implicit Index in Repeat. The authored VM counts Repeat iterations but does not establish that pseudo-variable. The final lookup uses an explicit counter and While instead. The VM is not changed and no ceiling is raised. An initial test also incorrectly expected an untyped parameter to inherit its global's type; the corrected test records that it is unknown. Failed prototypes and test assumptions are not acceptance evidence.

Scan advancement and literal-inference loops use numeric control flags, not a mutable Text sentinel in a loop condition. The latter exposed inherited native constant-string propagation behavior in an abandoned compaction attempt; native probes caught it. No unrelated native-emitter change is included.

The next full-source reproduction attempt hit the launcher's unchanged 65,536-entry **aggregate** collection backing store during the final output copy. This was not runaway CompilerOutput: at aggregate entry 65,000, CompilerOutput had 5,213 entries and BytecodeOut had the expected 9,450. Token, AST, IR, bytecode, copied output and retained checker metadata all share that backing store. The final scanner reduces its source/bytecode footprint, reads parameter facts directly from tokens and reuses depth-indexed frame rows. No VM/runtime repair, capacity increase, partial self-reproduction or weakened large-initializer test is substituted for the original full reproduction gate.

After compacting below that aggregate budget, a separate reproduction attempt exhausted the native launcher's unchanged 2,097,152-byte character arena in `VMDecodeConstant`. A scratch debugger classified the precise overflow; the integer backing-store estimate was not evidence that all budgets were satisfied. The checker now stops unique-name lookups at the first match, skips unknown-type insertions before lookup, and recognizes unambiguous assignments before invoking parser lookahead. These reduce redundant interpreted work without changing constant decoding, raw VM behavior or either ceiling. The candidate's direct-native accounting predicts 65,481 aggregate entries (55 spare); this very small headroom is a remaining bootstrap constraint, not room to wire in the complete semantic passes.
