# Sparse closure facts: promising, still test-only

A large seeded closure workload spends substantial work carrying scalar and unknown facts through branches and loops. A test-only sparse representation removes those exact default facts and emits identical assembly, while reducing mapping and merge work. **No production compiler or runtime file changes in this follow-up.** The experiment is stacked on [PR #71](https://github.com/Shibukedang27/Kuro/pull/71), verified open at `eee9a69ac09a14d0e33d4be9610c03819c9f1282`, based directly on PR #70's `perf/prune-empty-closure-return-analysis` branch. That predecessor head had eight successful checks before this work started; it remains unmerged.

## What changed and why

`scripts/profile_sparse_closures.py` builds seeded IR containing numeric-local pressure, reconverging closure-target diamonds, a loop, aliases through `LOADVAR`/`STORE_LIST`/`UPDATE`, one-sided local definitions, unreachable returns, reverse-order call chains, and seeded recursion. The stress Action has 344 instructions at size 80 and 614 at size 160. Other functions are analyzed too: the counters below cover the complete workload, not just that Action. The loop is an analysis fixture, not a program intended for execution; no runtime-performance or termination claim follows from it.

The CLI also compares mixed known/scalar returns, missing-target returns, overwritten closures, zero-iteration loop paths, an unreachable scalar return, and eight separately generated graphs. The graph generator varies reachable diamond depth, optional loop structure, aliases and one-sided locals, and known/missing/scalar return forms. These are deterministic structured graphs, not arbitrary-IR fuzzing. The ordinary regression uses seeds 0–7; the retained opt-in profiles use 7319–7326. There are 14 cases per profile, with five successful assembly outcomes and nine deliberate errors.

Three implementations are compared: unchanged production; an independent legacy AST clone restoring exactly two whole-state deep-copy sites and removing exactly one seedless guard; and the sparse AST clone. The legacy clone does not inherit either PR #70's pruning or PR #71's shallow state copies, but deliberately shares the rest of the compiler. Every case compares **complete assembly strings or exact `NativeBackendError` type and message**, then repeats that comparison with all three instrumented emitters. AST shape assertions fail closed if expected state/default/copy/join sites change. This is not an oracle independent of all existing analyzer behavior.

## The safety boundary

A missing name means `(empty targets, False)`. The prototype omits **only** that exact fact when directly assigning to its test-only `SparseFacts` mapping. Reads and joins keep production's default, target-set union, and all-paths-known AND unchanged. For example, `({A}, True)` joined with an absent name must become `({A}, False)`, not a known closure and not an omitted entry. The regression explicitly checks that nonempty/unknown facts survive and that empty/known facts remain explicit. Empty/known is not currently generated by the analyzer, but the representation does not silently conflate it with missing.

Copies own a fresh mapping while sharing read-only target sets. Transfers replace facts and merges allocate unions, as in PR #71; no shared set is mutated in place. The prototype additionally copies target sets on nondefault assignments. `SparseFacts` is **not** a general-purpose replacement for `dict`: it relies on this analyzer's direct assignment and canonical-map-copy usage, not every inherited mutating dictionary API. Production adoption should not expose that trap.

Dropping explicit defaults changes representation equality and therefore suppresses redundant worklist requeues. It is not merely another allocation optimization. The sticky `all_returns_known` flag, accumulated return targets, pending order, outer fixed-point order and bound are otherwise untouched. The reduced visit count is measured below, rather than presented as unchanged convergence behavior.

## Exact local results

The retained [machine-readable measurements](sparse-closure-profile.json) include interpreter/platform, predecessor HEAD, compiler and script SHA-256, complete per-case counters and mapping-size histograms, raw timing repetitions, and assembly lengths/digests. The production directory was clean for both runs. Timings were repeated sequentially on Linux x86-64 with Python 3.12.3, without a concurrent local test suite; emitters run in a fixed production/legacy/sparse order in one process. No CPU pinning, process-hash pinning, allocation profiler, or cross-platform performance comparison was performed. Instrumented runs are separate from uninstrumented emission timing.

| Identical assembly bytes | 85,510 | 106,824 |
| Production uninstrumented emission, three runs | 1.758–1.931s | 11.217–12.352s |
| Unpruned deep-copy reference, three runs | 2.068–2.217s | 22.089–22.581s |
| Test-only sparse emission, three runs | 0.266–0.274s | 1.262–1.295s |

The size-80 assembly SHA-256 is `644da9482236a1c5d78ba3daf13a8ce3d3161c1b524dcb9eeb5c75dd045e384d`; size 160 is `0a5907faf39c0feba981eb0f49d6889060ccde11eb4542908084787e92e2538f`. Equality was checked on all bytes, not inferred from the digest. The nine negative cases all preserve `compiler.native.NativeBackendError` with `x86_64-linux Invoke requires closures with statically known targets`.

The legacy clone makes 76 analyzer calls, copies/deep-clones 7,061,692 entries, and makes the same 17,300 merge attempts as production. Its instrumented merge time was 8.165s: timing noise and different allocation history make that unsuitable for claiming a production-versus-legacy merge speedup. The operation counts, rather than a single instrumented duration, establish where work is avoided.

The complete local suite passed **1,041 tests, 20 skipped in 162.46s**. The new file contributes three tests, including one multi-case differential test; test count is not corpus-case count. No tests, targets, Python versions, or CI jobs were removed. The final documentation-updated PR head must have all eight checks successful before completion; earlier-head results do not substitute.

## Reproduce

Use the repository's installed test interpreter (here `.venv/bin/python`):

```sh
.venv/bin/python -m pytest -q tests/compiler/test_sparse_closure_analysis.py
.venv/bin/python scripts/profile_sparse_closures.py --output /tmp/sparse80/profile --size 80 --repeat 3 --random-cases 8
.venv/bin/python scripts/profile_sparse_closures.py --output /tmp/sparse160/profile --size 160 --repeat 3 --random-cases 8
.venv/bin/python -m pytest -q --durations=20
```

The CLI writes full assembly files for positive cases and a JSON report containing complete outcomes, all repetitions, and fresh per-case instrumented counters. Checked-in evidence replaces repeated assembly text with byte counts/digests only **after** full equality checks. These opt-in measurements run legacy deep copies and can take minutes. Their source HEAD is the predecessor because the experiment files were not yet committed; script/production hashes disambiguate the measured code.

## Why production is unchanged, and the next experiment

This is positive evidence for a sparse representation, not evidence of a problem with PR #71. It does not yet establish that a narrowly scoped production patch should use this dictionary subclass or change scheduling. The corpus is finite, largely structured, and emitted-output equivalence does not expose every intermediate return-summary transition. The stored nonempty/unknown count being equal is useful evidence, not a proof over arbitrary graphs. Existing analyzer behavior, including sticky return accumulation, is deliberately preserved rather than independently redesigned.

The next bounded step is a **test-only normalized plain-dictionary variant** with explicit write/pop sites and no inherited-mutator dependency. Compare each analyzer invocation's exact `(returned targets, all_returns_known, saw_return)` triple against the unpruned deep-copy reference over bounded generated CFGs with multiple backedges, swapped predecessor orders, missing-name joins and changing recursive summaries. Record an old/new state relation where dense explicit defaults normalize to sparse absence; explain each suppressed queue event before considering production. Benchmark that variant with allocation measurements, controlled process hash/order and fresh processes at both existing sizes. Promote only if exact emitted outcomes and summary traces match and the reduced entry work survives without subclass-specific overhead or hidden semantics changes. Do not combine numeric inference, CFG caching or worklist redesign with that patch.

A full clean-checkout Python-free compiler/runtime construction and replacement of host assemblers/linkers remain unfinished. This experiment improves the evidence for one hosted-bootstrap bottleneck; it does not remove a foreign toolchain dependency or complete [the independence roadmap](independence-status.md). Keep the entire PR stack open and unmerged.
