# Metadata can follow rows, but generation IDs still need a policy

## What this increment establishes

This test/design-only increment starts directly above draft/open [PR #119](https://github.com/Shibukedang27/Kuro/pull/119), exact parent `da98dc3b40126259a2bd07ac0c3fefa91aaf8781`. It changes no production source, distribution image, eager admission rule, resource ceiling or consumer. It does not install a ledger, linked-list implementation, sharing, reclamation or an overflow guard.

The [row-funded layout model](../../tests/self_host/test_vm_row_funded_metadata.py) removes the need for a retained descriptor for every generation. It compares a linked-row candidate against the independent eager-list oracle over 131,072 four-operation traces, including exact destructive destination prefixes at terminal row admission. A separate churn control performs 65,537 empty reset/copy pairs with three binding slots, zero rows and zero row links; later publication keeps historical chains intact. This is a specification model, not a native allocator or an all-consumer lifetime proof.

The [seeded ID-boundary witnesses](../../tests/self_host/test_vm_generation_id_bounds.py) expose another blocker: unchanged Linux x86-64 production helpers use signed native arithmetic. After allocating ID `2**63 - 1`, the next reset publishes a negative ID that ordinary collection lookup treats as inactive. Append to that name sets `VMFailed`, while the previous positive generation remains readable with its raw/display pair. Hosted execution instead allocates `2**63` and appends successfully. The driver deliberately seeds the counter near the boundary using small runtime literals; it does **not** execute `2**63` resets, prove natural reachability, establish all backends, or approve wrapping as a language contract.

## A representation with no per-generation table

Keep one descriptor per existing name slot: generation ID, head row index, tail row index and logical length. Inactive slots retain their name but have no active binding. An empty active generation has head/tail `-1` and length zero. Reset replaces that slot's descriptor and advances the generation counter. It allocates no historical-generation descriptor and never deletes or reuses a historical row. The ID is a label, never an array index.

Retain each published row's owner ID and immutable scalar raw/display pair, and add one following-row index. Append first passes the existing eager admission point; then it publishes a new row and connects the previous tail belonging to the same generation. Interleaving other names' appends cannot mix the chains. Set replaces only a selected row's scalar pair and spends no row. Deactivation and reset neither refund logical debit nor reclaim row storage. The model checks every retained historical chain as well as active bindings; temporary dictionaries used to check those invariants are not retained candidate metadata.

For `N` retained name slots and `R` published historical rows, the candidate needs four descriptor fields per name and one link per row, independent of the number of empty resets/copies. Relative to existing IDs/owners/value/display storage, the proposed extra fields are three per name and one per row. With 64-bit fields and both existing native capacities at 65,536, a fully preallocated implementation would add 2,097,152 bytes of payload, excluding headers, alignment, seeds and ledger scalars. This arithmetic is a sizing estimate, **not** a measured native image or memory-allocation compatibility result. Additional memory can itself fail; no claim of identical system-resource failures follows from an entry-count bound.

The later [native metadata budget probe](vm-native-metadata-budget.md) measures these four ordinary integer arrays through the unchanged Linux backend: it reserves **4,194,336 extra zero-fill bytes**, including per-element length sidecars and logical-length cells. The payload-only estimate above is not the actual backend reservation budget; neither figure certifies a complete linked ledger or system-allocation-failure compatibility.

Each valid row link fits `-1..65,535`, and each per-name length fits `0..65,536` at the current native row ceiling. Descriptor count is bounded by names already retained in the existing name arrays, not by historical IDs. A future hosted implementation must grow alongside its existing storage rather than inherit native ceilings. Atomicity and ordering of multiple native array writes still require implementation-level proof; Python list append is not that proof.

## Copy and readers

Copy preserves equal-name early return and missing-source failure precedence. After successful late source lookup, it captures the source head and length before resetting the destination. It captures each scalar cell and following index before publishing the destination row. Unique active ownership and synchronous non-reentry mean destination appends do not modify the source chain. There is no bulk reservation: the destination retains precisely the paid prefix if a later row hits terminal admission. Sequential multi-store retains an earlier completed destination and the later partial one.

This model has no public borrowed-reader API. It does not extend or replace the [scoped-reader obligation](vm-nonsharing-ledger-protocol.md). A local row index is not a reusable external handle, a paid alias, or a safe asynchronous pin. Historical chain retention here is not permission to reclaim or share any row.

## ID bounds are a separate compatibility decision

Bounding metadata by rows avoids indexing metadata with a generation ID, but it does not solve ID arithmetic. Existing negative IDs mean inactive names. The current native signed wrap observed by the seeded probe therefore violates the candidate's unique, nonnegative, monotonic ID invariant; hosted Python integers do not share that boundary. A maximum-ID guard would add or change observable failure behavior. Resetting or compacting IDs could collide with historical owner labels and would require a separately proved translation/epoch protocol. Neither is silently installed here.

Consequently, this increment does not authorize a production migration. An explicit supported-history and overflow policy must be selected and tested for every backend; the full compiler's practical count is not a proof for arbitrary programs. The finite successful churn witness from #119 remains valid, but neither it nor this probe licenses unlimited native IDs or an arbitrary larger generation table.

Independent representation analysis also identified a distinct alternative: remove generation counters entirely, use per-name `-1 = inactive`, `-2 = active empty`, or a nonnegative head row index, and repurpose the existing owner column as next-row links. Without a tail table, Append would traverse to the tail, avoiding a new backing buffer at a potentially quadratic runtime cost. This is **not** the model implemented here: it changes internal ID/owner observability and removes the current wrap behavior rather than preserving it. It needs its own sentinel, consumer, resource and compatibility proof. Neither alternative may be treated as already approved production metadata.

## Acceptance evidence and remaining work

The new layout alphabet covers positive Get, valid/invalid Set, Append, reset, deactivation, replacement, eager copy, inactive/self/missing copy, terminal partial prefixes and sequential multi-store. Directed controls cover interleaved links, raw/display preservation, historical retention, full-budget Set and hosted-style no-ceiling mode. The hosted control is separate because the existing finite eager oracle does not accept `None` as a ceiling. Exhaustive depth four over two names and two small budgets is bounded evidence, not an inductive proof for arbitrary histories.

Focused tests, independent frozen-head review, full suite, fresh four-image rebuild, blocked-toolchain smoke, fresh compiler-bytecode reproduction/272-literal control and all eight exact-head CI checks are required acceptance gates. Results and immutable head are recorded in the PR verification receipt; a parent's checks cannot certify this head.

Before any migration, audit Get (including negative logical-end offsets), Length, Print, Copy, Set, Append, reset, scalar replacement, marker decoding, moving Text, result/frame/closure paths and sequential multi-store. Preserve late name resolution, raw/display capture, logical debit chronology, hosted behavior and native terminal admission. Prove every consumer's borrowing scope and every metadata write boundary, and resolve native ID exhaustion explicitly. Only a separate lifetime/credit proof can enable sharing, reentry or reclamation.

No production performance, capacity or headroom gain is claimed. Historical full-compiler peak remains 65,481 rows with 55 spare, not newly measured here. Python bootstrap seeding and Clang/LLVM assembly/linking still block strict independence; scalar provenance and the complete authored semantic gate remain unfinished. PR #107/#108 remain individually unverified. This PR and its ancestors must remain draft/open/unmerged.
